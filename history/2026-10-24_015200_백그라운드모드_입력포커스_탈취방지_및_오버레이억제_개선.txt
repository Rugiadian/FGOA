[요청 내용 / User Request]
백그라운드 모드일 때 마우스 조작을 가로채진 않는데 채팅 입력 포커스를 빼앗기는 순간들이 있는 현상 분석 및 해결

[원인 분석 / Root Cause Analysis]
1. 액션 시각화 오버레이 윈도우(ActionOverlayWindow)의 주기적 표시/숨김:
   - 각 액션 시퀀스 실행 시 show_sequence()가 호출되어 투명 오버레이 윈도우(ActionOverlayWindow)가 화면에 표시(show)되고, 500ms 후 hide()되는 과정이 반복됨.
   - 비록 WA_ShowWithoutActivating 속성이 있더라도, Windows DWM(데스크톱 창 관리자) 환경에서 최상위 윈도우가 생성/표시/소멸되는 순간 사용자가 입력 중이던 채팅/문서 창의 포커스 큐가 순간적으로 교란되거나 Z-order 재계산으로 포커스를 잃는 현상 발생.
   - 백그라운드 모드에서는 타겟 창이 다른 창 뒤에 가려져 있으므로 오버레이 팝업 자체가 불필요함.

2. 타겟 윈도우의 Win32 클릭 수신 시 포커스 활성화 (Activation):
   - PostMessage로 WM_LBUTTONDOWN을 수신한 타겟 창(에뮬레이터, 게임, 브라우저 등)이 자체 윈도우 프로시저(DefWindowProc 또는 내부 핸들러)에서 SetFocus/SetActiveWindow/SetForegroundWindow를 호출하여 포커스를 가져가려는 시도가 발생.

[해결 및 개선 내역 / Implementation Details]
1. 백그라운드 모드 시 액션 오버레이 팝업 원천 억제:
   - ui/main_window_parts/playback_controller.py:
     - _on_action_sequence_started_visual 및 _on_action_executing_visual에서 백그라운드 모드 활성화 시 ActionOverlayWindow 팝업을 원천 차단하여 OS 레벨의 창 깜빡임 및 포커스 교란 완벽 방지.
     - 백그라운드 모드 토글 시(_on_toggle_background_mode) 이미 떠 있는 오버레이가 있다면 즉시 정리(clear_action).

2. 타겟 윈도우 WS_EX_NOACTIVATE 스타일 적용 & 포커스 가드(Focus Guard):
   - core/input_controller.py:
     - ensure_no_activate_style(hwnd): 백그라운드 클릭/드래그/키 입력 전 타겟 윈도우에 WS_EX_NOACTIVATE(0x08000000) 확장 스타일을 적용하여 Windows OS 커널이 마우스 메시지 수신 시 포커스를 넘겨주지 않도록 차단.
     - LockSetForegroundWindow(LSFW_LOCK=1): 클릭 전송 중 다른 프로세스의 포커스 변경 호출을 OS 레벨에서 일시 잠금.
     - restore_foreground_window(fg_hwnd): 메시지 전송 전 사용자의 현재 활성 창(GetForegroundWindow) 핸들을 캡처하고, 전송 후 만약 포커스가 이탈했을 경우 AttachThreadInput 기반으로 1밀리초 이내에 원래 창으로 즉각 포커스 복원.
     - post_click_at, post_drag_and_drop, post_text, post_key_combination 모두에 동일한 포커스 보호 가드 적용.

3. 플로팅 UI 및 팝업 플레이바 포커스 비활성화 강화:
   - ui/action_overlay.py: show() 호출을 Windows API의 ShowWindow(..., SW_SHOWNOACTIVATE)로 교체.
   - ui/floating_stop_widget.py & ui/popup_play_bar.py: showEvent 시 네이티브 HWND에 WS_EX_NOACTIVATE 스타일 적용 및 Qt.WA_ShowWithoutActivating 보장.

4. 기존 평가기 evaluate 2인자 하위 호환성 보장:
   - core/runner.py: background_mode가 False일 때 기존과 동일하게 evaluate(condition, hwnd) 2개 인자로 호출하도록 분기하여 기존 모의 테스트와의 100% 호환성 유지.
